# Hey, I'm Ember

I spend most of my days writing Python scripts that quietly keep systems running without anyone noticing. Automation is the part of software that still feels like magic to me — a few dozen lines that turn a weekly chore into something that just happens.

## What I care about

**Python** is my default language. I like how readable it stays even when the logic gets complicated. Most of the tools I build start as small scripts and grow only when they need to.

**Automation** is where I put the most energy. Whether it's CI pipelines, scheduled jobs, or glue code between services, I try to remove the repetitive steps so people can focus on the interesting problems.

**Cloud** work keeps showing up. I work with the usual suspects — containers, serverless functions, object storage — and I prefer designs that stay simple and cheap to operate.

**Developer tools** fascinate me. Anything that shortens the distance between an idea and a working prototype is worth improving. I’ve spent a fair amount of time tuning local environments and small CLIs that make daily work less friction-heavy.

## How I work

I favor clear code over clever code. Comments that explain *why* matter more to me than comments that restate the *what*. I test the paths that actually break in production, and I leave the rest alone until they prove they need attention.

When something fails, I want logs that tell a story instead of a wall of stack traces. When something succeeds, I want it to stay quiet.

## Currently exploring

- Better patterns for long-running Python services in cloud environments
- Lightweight automation frameworks that don’t require a whole platform
- Small developer utilities that solve one problem well

If any of that overlaps with what you’re working on, feel free to open an issue or start a discussion. I’m always interested in practical approaches that actually ship.

Thanks for stopping by.
